## 1. 目标与边界

### 1.1 目标

基于当前 Spring Boot 后端已有接口，开发患者、医生、管理三类角色的前端页面，形成可联调的完整就医流程。

患者端覆盖：

- 注册、登录与登录态恢复
- AI 导诊问答
- 科室、医生、排班浏览
- 选择就诊人并挂号
- 模拟支付、订单查询、退号、签到
- 就诊人管理
- 检验报告查询

医生端覆盖：

- 选择排班
- 查看候诊队列
- 叫号
- 开具检验报告

管理端覆盖：

- 科室增删改查
- 医生增删改查
- 排班增删改查

### 1.2 非目标

以下内容不在本期前端范围内：

- 修改任何后端代码、配置、数据库脚本或依赖
- 管理端数据看板
- 管理端挂号订单审核
- 医生账号与医生档案绑定
- 医生历史报告列表
- 真实微信或支付宝支付
- 后端尚未实现的 SSE、RAG 展示或向量检索界面

## 2. 后端事实与约束

接口契约以实际 Controller、DTO、VO 和 Service 为准，不采用过期文档中的路径。

- 后端：Spring Boot 3.2.5、JDK 17、MySQL 8、Redis
- 服务端口：`8080`
- 鉴权：无状态 JWT，请求头 `Authorization: Bearer {token}`
- 角色：`0` 患者、`1` 管理员、`2` 医生
- 统一响应：`Result { code, msg, data }`
- 分页响应：`PageResult { total, records }`
- 业务错误通常返回 HTTP 200，前端必须检查 `code`
- 未登录：HTTP 401 / `code=3001`
- 无权限：HTTP 403 / `code=3002`
- 日期格式：`yyyy-MM-dd`
- 时间格式：`yyyy-MM-dd HH:mm:ss`
- 时区：`Asia/Shanghai`

关键接口：

- 认证：`POST /auth/register`、`POST /auth/login`、`GET /auth/me`
- 患者：`GET /patient/list`、`POST /patient`、`PUT /patient`
- 科室：`GET /department/list`
- 医生：`GET /doctor/list?departmentId=`
- 排班：`GET /schedule/list?doctorId=&days=`
- 订单：`POST /order`、`GET /order/list`、`POST /order/sign`
- 支付：`POST /payment/pay`、`POST /payment/refund`
- 报告：`GET /report/list`
- 导诊：`POST /triage/ask`
- 医生工作台：`GET /doctor-work/waiting`、`POST /doctor-work/call`、`POST /doctor-work/report`
- 管理端：`/admin/department`、`/admin/doctor`、`/admin/schedule` 的 CRUD 与分页接口

## 4. 应用架构

### 4.1 路由与角色

公共路由：

- `/login`
- `/register`

患者路由：

- `/patient/home`
- `/patient/departments`
- `/patient/doctors`
- `/patient/schedules`
- `/patient/booking`
- `/patient/orders`
- `/patient/patients`
- `/patient/reports`
- `/patient/triage`

医生路由：

- `/doctor/workbench`

管理路由：

- `/admin/departments`
- `/admin/doctors`
- `/admin/schedules`

路由守卫规则：

- 未登录访问受保护页面时跳转 `/login`
- 角色不匹配时跳转该角色首页
- 登录成功后按角色跳转
- 401 清除登录态并跳转登录页
- 403 展示无权限页面或提示，不反复请求

### 4.2 登录态

- JWT 默认保存在 `sessionStorage`
- Pinia 保存当前用户、角色和 token
- 应用启动时调用 `/auth/me` 恢复用户信息
- 退出登录时清除 token 和用户状态
- 不把密码写入持久化存储

### 4.3 API 层

- Axios 基础地址：`/api`
- 开发环境由 Vite 代理到 `http://localhost:8080`
- 代理移除 `/api` 前缀
- 请求自动添加 Bearer token
- 响应统一解包 `Result`
- `code !== 200` 时抛出包含 `code` 和 `msg` 的业务错误
- 网络错误、超时和 5xx 统一转换为用户可理解的提示
- API 模块按认证、患者、科室、医生、排班、订单、支付、报告、导诊、医生工作台、管理端拆分

### 4.4 状态管理

- Pinia 负责全局登录态
- 页面数据通过 composable 管理加载、错误和刷新
- 不使用全局状态存放全部表格和表单数据
- 操作成功后刷新对应列表或详情
- 不使用乐观更新掩盖后端真实状态

## 5. 页面设计

### 5.1 患者端

采用手机优先布局，覆盖 360px 宽度。

首页：

- 展示用户问候
- 提供症状描述入口和 AI 导诊入口
- 提供预约挂号、我的订单、报告查询快捷入口
- 展示科室列表和公开科室信息

挂号流程：

1. 选择科室
2. 选择医生
3. 选择排班日期与时段
4. 选择就诊人
5. 确认挂号信息并提交
6. 进入模拟支付
7. 返回订单列表

选择控件规则：

- 科室显示科室名称，提交 `departmentId`
- 医生显示医生姓名，提交 `doctorId`
- 排班显示日期、时段和医生名称，提交 `scheduleId`
- 就诊人显示姓名和关系，提交 `patientId`
- 订单操作使用订单对象中的 `id`，不要求用户输入 id

订单页：

- 分页展示订单
- 展示订单号、就诊人、就诊日期、时段、金额、状态和支付截止时间
- 待支付订单提供模拟支付，并展示支付截止时间；超时后由后端自动释放
- 已支付订单按后端规则提供退号或签到
- 支付截止时间使用倒计时
- 所有状态操作最终以后端返回为准

就诊人页：

- 展示就诊人列表
- 新增和编辑就诊人
- 关系使用中文选项
- 手机号、身份证长度与格式按 DTO 校验

报告页：

- 展示当前账号全部就诊人的报告
- 展示报告类型、标题、内容和报告时间

AI 导诊页：

- 输入症状描述
- 展示推荐科室、原因、紧急提示和来源
- 无匹配结果时引导补充症状或到导诊台咨询
- 请求过频时按后端提示稍后重试

### 5.2 医生端

采用桌面工作台，布局为“单栏候诊队列 + 右侧报告抽屉”。

- 排班选择器显示排班名称，不显示原始 id
- 本期排班选项来自 `src/mocks/doctorSchedules.ts`
- 页面以最小标注说明当前为演示排班数据
- 提交 `scheduleId` 给后端
- 候诊队列按后端返回顺序展示序号、就诊人、订单号和签到时间
- 叫号按钮调用 `POST /doctor-work/call`
- 空队列时禁用叫号并展示空状态
- 点击患者后打开右侧抽屉
- 抽屉内填写报告类型、标题和内容
- 完成就诊并开具报告后刷新队列

### 5.3 管理端

采用深色侧栏 + 顶部栏 + 表格布局。

科室管理：

- 分页展示，当前页支持按名称前端筛选
- 新增、编辑、删除科室
- 删除前确认
- 后端拒绝删除时展示具体原因

医生管理：

- 分页展示，当前页支持按姓名前端筛选
- 新增、编辑、删除医生
- 科室选择显示名称，提交 `departmentId`
- 本期不提供医生账号绑定字段

排班管理：

- 按医生筛选
- 新增、编辑、删除排班
- 医生选择显示姓名，提交 `doctorId`
- 时段使用上午、下午、晚间中文选项
- 日期不得早于今天
- 放号数量和金额按 DTO 规则校验

## 8. 错误处理与业务规则

### 8.1 通用错误

- 加载失败：展示错误原因和重试按钮
- 空数据：展示与当前页面匹配的空状态
- 无权限：展示无权限提示
- 网络断开：提示检查网络或后端服务
- 重复提交：提交期间禁用按钮

### 8.2 关键业务错误

前端直接展示后端 `msg`，常见场景包括：

- 号源已约满
- 当前排班不可预约
- 就诊人已预约过该排班
- 订单不存在或无权操作
- 订单状态不允许操作
- 支付超时
- 就诊时段已开始，无法退号
- 当前不在可签到时间
- 请勿重复签到
- 当前账号未绑定医生
- 当前无待就诊患者
- 订单尚未就诊完成，无法开具报告
- 导诊请求过于频繁

### 8.3 时间规则

- 支付截止时间来自订单 `deadlineTime`
- 签到仅在后端允许的时间窗口内可操作
- 退号仅在后端允许的时间窗口内可操作
- 前端预判用于改善体验，不作为最终权限判断
